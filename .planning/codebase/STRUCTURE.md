# Codebase Structure

**Analysis Date:** 2026-04-01

## Directory Layout

```
Tamagotchi/
├── tamago/                  # Executable entry point
│   └── main.go              # Application bootstrap and terminal launching
├── internal/                # Go internal packages (not importable by external projects)
│   ├── model/               # Core game state and business logic
│   ├── ui/                  # Terminal UI and Bubble Tea integration
│   ├── dungeon/             # Dungeon RPG system
│   └── persistence/         # Save/load and offline simulation
├── .planning/               # GSD planning documents
├── .docker/                 # Docker configuration
├── go.mod                   # Go module definition and dependencies
├── go.sum                   # Go dependency checksums
├── README.md                # Project documentation and feature overview
├── DUNGEON.md               # Detailed dungeon system documentation
├── docker-compose.yml       # Docker Compose configuration for running in container
└── tasks.md                 # Development tasks and TODOs
```

## Directory Purposes

**`tamago/`:**
- Purpose: Executable package containing application entry point
- Contains: Go package `main` with `main()` function
- Key files: `tamago/main.go` (bootstrap, save loading, Bubble Tea initialization)

**`internal/model/`:**
- Purpose: Core game state structures and logic
- Contains: Pet model, evolution stages, achievement system, event definitions, XP/leveling
- Key files:
  - `tama.go`: Main `Tama` struct with vital stats (hunger, thirst, sleepiness, happiness, anger, weight)
  - `evolution.go`: `Stage` enum and stage-related behavior (decay rates, animations)
  - `achievements.go`: Achievement definitions and unlock logic
  - `events.go`: Event definitions for interactive moments during gameplay

**`internal/ui/`:**
- Purpose: Terminal UI rendering and user interaction handling
- Contains: Bubble Tea TUI model, view rendering, command processing, animation frames
- Key files:
  - `tui.go`: Main `Model` struct, initialization, integration with Bubble Tea
  - `view.go`: Layout computation, responsive sizing logic
  - `update.go`: Command processing (feed, water, pet, sleep, etc.), stat modification, lifecycle ticks
  - `minigames.go`: Game mode handling (dungeon entry, mini-game state)
  - `dungeon_view.go`: Dungeon-specific UI rendering

**`internal/dungeon/`:**
- Purpose: Self-contained dungeon RPG mechanics
- Contains: Phase state machine, combat engine, enemy pools, equipment, floor generation, biomes
- Key files:
  - `dungeon.go`: `DungeonRun` state machine orchestration and phase handlers
  - `combat.go`: Turn-based combat engine (`Combat` struct, action resolution)
  - `enemy.go`: Enemy definitions and per-floor enemy pools
  - `floor.go`: Floor generation (room types, layout)
  - `equipment.go`: Equipment definitions, rarities, stat bonuses
  - `items.go`: Consumable items (potions, elixirs)
  - `stats.go`: Combat stat derivation from pet stats and equipment
  - `biome.go`: Biome definitions and combat modifiers
  - `ascii_art.go`: ASCII art representations of enemies

**`internal/persistence/`:**
- Purpose: Game state serialization and offline handling
- Contains: JSON save/load, offline tick simulation
- Key files:
  - `save.go`: `Save()` to JSON file, `Load()` from file, offline degradation via `applyOfflineTick()`

**`.planning/`:**
- Purpose: GSD (Getting Stuff Done) planning documents
- Contains: Architecture, structure, conventions, and concerns analysis
- Generated by: `/gsd:map-codebase` orchestrator commands

**`.docker/`:**
- Purpose: Docker build and runtime configuration
- Contains: Dockerfile for containerized game environment

## Key File Locations

**Entry Points:**
- `tamago/main.go`: Application bootstrap; handles platform-specific terminal launching (macOS), save loading, pet initialization
- `internal/ui/tui.go`: `InitialModel()` creates TUI model; `Update()` handles tick/input, `View()` renders

**Configuration:**
- `go.mod`: Module name (`Pessoal`), Go version (1.25), Bubble Tea and related dependencies
- `docker-compose.yml`: Service configuration for containerized game environment

**Core Logic:**
- `internal/model/tama.go`: Pet state (vital stats, XP, level, stage, achievement tracking)
- `internal/model/evolution.go`: Stage progression and decay multipliers
- `internal/ui/update.go`: Command implementation (feed, water, pet, sleep, exercise, annoy)
- `internal/dungeon/dungeon.go`: Dungeon state machine and phase orchestration
- `internal/dungeon/combat.go`: Turn-based combat resolution

**Testing:**
- `internal/dungeon/biome_test.go`: Tests for biome system
- `internal/persistence/save_test.go`: Tests for save/load functionality

## Naming Conventions

**Files:**
- Pattern: `snake_case.go` for Go source files
- Examples: `tui.go`, `dungeon.go`, `ascii_art.go`, `combat.go`

**Directories:**
- Pattern: `lowercase` for all internal package directories
- Examples: `model/`, `ui/`, `dungeon/`, `persistence/`
- No underscores or capitals in directory names

**Functions:**
- Pattern: PascalCase for exported functions (public), camelCase for unexported (private)
- Examples: `InitialModel()`, `ToFeed()`, `AddXP()` (exported); `applyOfflineTick()`, `updateWeightStates()` (private)

**Types/Structs:**
- Pattern: PascalCase for all types
- Examples: `Tama`, `Model`, `DungeonRun`, `Combat`, `Equipment`, `Enemy`, `Stage`

**Constants:**
- Pattern: PascalCase for exported, camelCase for unexported
- Examples: `MaxHunger`, `MinHunger`, `SaveFile`, `MaxOfflineTicks`

## Where to Add New Code

**New Feature (e.g., new pet command like "exercise"):**
- Command implementation: `internal/ui/update.go` (add function like `Exercise()`)
- Model logic: `internal/model/tama.go` (add counter like `TotalExercises`)
- UI handling: `internal/ui/tui.go` (add case in command parser)
- Tests: Add test file if needed in relevant package (e.g., `internal/model/tama_test.go`)

**New Dungeon Subsystem (e.g., new enemy type, new biome):**
- Enemy definitions: `internal/dungeon/enemy.go` (add to `EnemyPool`)
- Biome definitions: `internal/dungeon/biome.go` (add to `BiomeList`)
- Combat mechanics: `internal/dungeon/combat.go` (if special combat rules)
- ASCII art: `internal/dungeon/ascii_art.go` (add enemy sprite)
- Tests: `internal/dungeon/biome_test.go` or similar

**New Achievement:**
- Definition: `internal/model/achievements.go` (add to `DefaultAchievements()`)
- Unlock logic: `internal/ui/update.go` or `internal/dungeon/dungeon.go` (check condition and call unlock)

**Shared Utilities:**
- Location: Create in relevant package (e.g., `internal/model/util.go` for pet-related helpers)
- No global `utils/` package; keep utilities close to their domain

**Config or Constants:**
- Stat ranges: `internal/model/tama.go` (MaxHunger, MinHunger, etc.)
- Dungeon thresholds: `internal/dungeon/dungeon.go` or `stats.go`
- UI styling: `internal/ui/tui.go` (style variables like `styleTitle`, `styleInput`)

## Special Directories

**`internal/` (Go Internal Package Convention):**
- Purpose: Code in `internal/` cannot be imported by external projects; enforces module boundary
- Generated: No
- Committed: Yes
- Rationale: Game code is monolithic and should not be reused externally

**`.planning/codebase/` (GSD Planning Output):**
- Purpose: Analysis documents (ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md)
- Generated: Yes (by `/gsd:map-codebase` commands)
- Committed: Yes
- Used by: `/gsd:plan-phase` and `/gsd:execute-phase` orchestrator commands

**`.git/` (Version Control):**
- Purpose: Git repository metadata
- Generated: Yes
- Committed: No (standard .gitignore)

**`node_modules/`, vendor:** Not present in this project (Go uses go.mod)

## File Organization by Domain

**Pet Lifecycle:**
- Model: `internal/model/tama.go`, `internal/model/evolution.go`
- UI: `internal/ui/update.go` (command functions), `internal/ui/view.go` (rendering)
- Persistence: `internal/persistence/save.go`

**Achievements:**
- Model: `internal/model/achievements.go` (definitions)
- Logic: Scattered in `internal/ui/update.go` (unlock checks) and `internal/dungeon/dungeon.go` (dungeon-specific unlocks)

**Dungeon/RPG:**
- All contained in: `internal/dungeon/` (self-contained)
- Integration: `internal/ui/minigames.go` (mode detection), `internal/ui/dungeon_view.go` (rendering)
